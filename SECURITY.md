# Security and deployment scope

This is a local development reference, not an admitted production system. Bind it to loopback. Remote use requires a separately qualified host with TLS, user authentication, authorization, anti-abuse/rate limits, secret rotation, backup/restore, retention/deletion, monitoring and deployment controls. Do not place server-owned operator keys in browser bundles.

Reports and audio can contain sensitive content. Use synthetic examples, private storage and explicit recording permission. Keep bodies, tokens and recordings out of diagnostic spans. No transcription or external telemetry collection is provided by default. A model opinion, a signed digest or a passing unit suite is not proof of safety.

The admission screen trusts an independently managed policy and pinned receipts. Never allow candidate code or authors to write that trusted policy. It does not authenticate reviewer identity or inspect referenced evidence itself. Its eligible result does not authorize release.

For a suspected vulnerability, avoid posting secrets or exploitable customer data in a public issue. Use GitHub's private vulnerability reporting if enabled for this repository; otherwise contact the repository owner privately through their published security contact. No response-time SLA or bug bounty is offered by this reference.
