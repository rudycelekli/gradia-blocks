# Contributing

Submit focused changes with a concrete user workflow, behavioral contract, supported runtime, configuration/feature semantics and runnable examples. Include source provenance, exact upstream revisions and licenses/notices for any reused code. Do not submit customer code, communications, recordings, credentials or private configurations without explicit rights.

Test positive behavior and meaningful negative cases: tenant/role separation, malformed input, persistence failure, retries/idempotency, concurrency, disabled features, audio limits and upgrade/recovery where relevant. Keep test generation separate from protected acceptance cases. Add evidence for accessibility and actual host composition when changing the widget.

The local admission screen checks an evidence envelope, not every possible behavior. Independent maintainers must inspect reports and authorize trusted receipt pins. Rights, maintainer and support gates require human reviewers. Contributors cannot approve their own policy or infer release permission from an eligible screen result. Pull requests are reviewed; this project does not auto-merge AI-approved submissions.

Use synthetic fixtures and describe what was actually tested. Proposed adapters and provider capabilities must remain labeled until separately qualified. Provider accounts, resale rights, commercial commitments and deployment authority are never granted by a contribution.
